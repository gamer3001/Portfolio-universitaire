Le problème

À l'IUT de Lille, l'emploi du temps passe par Hyperplanning — mais il n'existe aucune application dédiée pour le consulter au quotidien, seulement un flux ICS brut à importer soi-même dans un calendrier générique. Pas très pratique pour vérifier rapidement son prochain cours entre deux couloirs.

J'ai voulu une vraie interface, pensée comme Pronote ou École Directe : rapide, lisible, et qui se met à jour toute seule sans que j'aie à retélécharger quoi que ce soit.

Une interface pensée pour l'usage quotidien

Navigation jour par jour avec des flèches, un bouton calendrier pour basculer entre vue jour et vue semaine, un trait d'heure actuelle façon calendrier Apple, et une couleur différente par matière pour repérer un cours d'un coup d'œil. Volontairement sobre, pas un design "généré par IA".

Le dimanche est totalement écarté : les flèches le sautent automatiquement en navigation jour, et il n'apparaît tout simplement pas dans la vue semaine ni dans le mini-calendrier, puisqu'il n'y a jamais cours ce jour-là.

Vue mobile — navigation jour par jour

Vue PC — semaine en grille côte à côte

Deux versions, un seul site

index.html est pensé mobile-first, avec un bouton en haut pour basculer vers pc.html : une mise en page dédiée grand écran, avec la vue semaine en grille classique (colonnes côte à côte).

Synchronisation automatique

Un workflow GitHub Actions (sync-edt.yml) va chercher le fichier .ics d'Hyperplanning à intervalle régulier et le commit directement dans data/edt.ics. Le site n'a donc jamais besoin d'une intervention manuelle pour rester à jour.

Fiabilité du pipeline

  • Le job échoue clairement (au lieu de continuer silencieusement) si le secret est vide, si l'IUT répond mal, ou si le contenu récupéré n'est pas un vrai fichier ICS
  • Vérification que le contenu commence bien par BEGIN:VCALENDAR avant de l'utiliser
  • Logs détaillés dans l'Action : code HTTP reçu et taille du fichier téléchargé

Un site qui explique ses propres pannes

Plutôt que de rester bloqué sur un simple "chargement..." en cas de souci, le site affiche un panneau de diagnostic précis côté client : code d'erreur HTTP, message exact, et un bouton pour ouvrir directement data/edt.ics et vérifier le fichier brut en un clic.

Le petit outil qui manquait

IUTime ne révolutionne rien, mais il règle un vrai problème du quotidien : savoir en deux secondes où je dois être. C'est le genre de projet né d'une frustration simple — pas d'appli officielle — et résolu avec les outils que j'avais déjà sous la main.
